# Cosmos 实施设计与决策记录

状态：设计讨论中，未进入实现。创建日期：2026-10-21。

## 当前有效决定（实现时优先阅读）

本节汇总用户已经确认的需求；后面的分轮记录保留依据，早期问题和建议不代表未确认需求已生效。

- 运行：在目标主机启动 Cosmos；连接端只需要 SSH 和终端。会话断线后保留；本地也使用同样的软件。不集成 SSH 连接管理。
- 核心：Cosmos 自行实现主要业务与 UI，复用 Tmux 的稳定终端能力；当前 Tmux 作为隔离的后端适配器，不再以定制 Tmux 为主要路线。多连接体验仍参考 Tmux。
- 首版：输入法、统一查看器、命令建议、完整 Agent 均必需。先满足个人需求。
- 输入法：客户端共用开关，组字按客户端和窗格保存；切换窗格保留，断开取消。光标附近覆盖预编辑和候选两行；提交文字不附带回车。默认使用现有 rime_ice 配置；IBus 式终端前端与直接 librime 的技术取舍待验证。无候选释义。
- 命令建议：terminal_agent 完全并入；沿用现有命令生成与 Bash 回填语义，首版完整支持 Bash。
- 完整 Agent：允许用户显式创建多个专用窗口，各自绑定任务，不自动分屏；OpenCode 首发，预留其他后端。可发现本服务所有会话结构，按需读取输出，按用户指令操作，接入 OpenCode 权限机制。
- 查看器：统一入口、共享位图渲染层，格式适配分别实现；可独立运行，另有 Cosmos 协作接口。退出恢复进入前现场，底层进程持续运行。多页内容必须设计缓存与预加载。
- 文件类型：用户列出 PNG、JPG、WebP、EPS、SVG、PDF、ICO 作为格式模块方向；首版必需常见位图与 PDF；EPS、SVG、ICO 后置。动画先显示首帧，ICO 接入时自动选择合适尺寸。
- PDF：首版搜索与高亮定位；选择、复制、外部剪贴板仅预留接口；不做 OCR。
- 文件管理：保留选定 Yazi 版本的现有文件能力，统一改造 UI、布局与键位；提供专用窗口和可折叠左侧 panel。运行主机本地文件优先，不集成 SSH；未来协议预留。
- Mod：内置功能按公开接口拆开，支持手动注册可信外部程序；声明能力、管理生命周期，不承诺系统沙箱，不做插件市场。
- 设置：类似 Ctrl-P 的按需命令面板，默认只显示操作；设置和 Mod 进入相应子菜单，另有显示、键位、通知配置。Ctrl-P 仅是交互类比。
- 快捷键：保留命令入口，默认 Ctrl-B 为 Leader，在设置子菜单配置键位。
- 通知：统一接口和设置；服务级事件分发给所有客户端，各自在全局右下角呈现。高 1～2 行、按钮宽 3 显示列；不抢焦点，普通通知自动消失，需要处理的保留，用快捷键进入按钮。动作处理在服务级同步；普通关闭仅影响当前客户端。

## 1. 文档定位

本文承接《可扩展终端工作壳：最终设计规范》和《设计收获》，将研究方向转成可实现的模块边界、交互规则和验收条件。既有文档中的建议不自动视为用户已确认的决定；本文显式区分既定方向、待决策项和待验证假设。讨论期间不修改 terminal_agent 的实现。

## 2. 已有材料与约束

- 产品方向：以 Tmux 为核心的远程终端工作壳，默认界面保持普通终端形态。
- 空间原则：用户控制布局，不因安装或后台活动自动分屏、抢焦点。
- 呈现原则：候选、帮助等按需显示；图片与 PDF 临时替换窗格视图，退出恢复工作现场。
- 状态原则：任务生命周期与临时界面分离；客户端交互状态独立。
- 候选外观：候选之间无间隔，以交替背景区分；每页 6 个。小窗格仍需确定退化规则。
- 窗口切换：按会话、窗口、窗格组织为可折叠树。
- 安全原则：上下文可检查、可移除，命令预览、回填、执行分离。
- 研究建议而非已确认范围：优先中文输入和图片，Agent、PDF 后置。

## 3. 功能拆分草案

以下为逻辑边界，尚不决定仓库、语言或进程数量。

### 3.1 启动与环境

负责启动、连接、配置、依赖检查、终端能力探测、诊断与升级。需要决定是否使用独立 Tmux socket、配置与可执行文件，以及现有 Tmux 会话如何进入。

### 3.2 会话与对象管理

负责会话、窗口、窗格的稳定身份、对象关联与重连恢复。Tmux 持有终端和进程；Cosmos 只记录必要扩展信息。窗格被关闭或复用后，旧关联不得指向新对象。

### 3.3 呈现与输入路由

负责客户端局部浮层、底部输入、临时替换视图、焦点栈、按键分派、尺寸变化及异常恢复。Mod 提交呈现请求，不自行接管外层终端绘制。具体能力需要技术验证，不能仅凭脚本透传推定可行。

### 3.4 操作注册与 Mod 生命周期

统一注册命令、快捷键、帮助、配置命名空间、版本要求、启停及失败恢复。首版是否需要第三方 Mod 安装和权限隔离尚未决定。

### 3.5 中文输入

负责 librime 会话、组字、候选、翻页、直通及向绑定目标提交。释义来源、离线要求、切换目标时的组字保留策略待定。

### 3.6 图片传输与显示

负责远程文件读取、解码、尺寸限制、Kitty 图像传输、客户端资源身份、裁切与遮挡、清理、重连重建及降级。图片查看器使用该服务，不自行维护另一套显示状态。

### 3.7 图片与 PDF 查看器

负责适配、缩放、平移和退出恢复；PDF 额外负责页码、栅格化、取消与有界缓存。是否允许首版依赖外部栅格化程序待定。

### 3.8 Agent 与 Shell 适配

分开定义命令建议、上下文选择、完整 Agent 任务关联、运行状态和权限确认。Shell 适配负责命令缓冲区回填；Agent 后端负责模型通信。不能把向 PTY 写文本直接等同于准确回填或安全执行。

### 3.9 搜索与窗口导航

负责对象树、预览、搜索范围、选择和确认跳转。研究中的活动热度、跨历史搜索范围仍待确定。

### 3.10 状态、配置与诊断

负责主题角色、后台通知、持久数据、缓存、日志脱敏和故障报告。权限声明、用户提示与真正的进程隔离是不同能力，需分别定义承诺。

## 4. terminal_agent 接入评估

基于 README、模块结构及 backend 实现的静态检查；本轮未运行模型或终端验收。

- 已有结构：Python UI、OpenCode 后端、配置与存储、Bash 脚本、C Readline 适配器相互分层。
- 当前用途：单行请求生成命令，工具被禁用，命令回填 Bash 后由用户执行。
- 可复用候选：配置和存储经验、后端事件解析、命令建议流程、Bash 缓冲区操作及现有回归用例。
- 需要改造：统一 Cosmos 配置命名空间、对象关联、生命周期和后端接口；决定独立使用方式是否保留。
- 呈现迁移：现有 Python/Readline 下方单行绘制，不能未经验证便与 Cosmos 外层绘制同时启用；应决定由谁持有绘制权。
- 任务差距：现有本地上下文与打开完整 OpenCode 的行为，不足以证明快捷输入和完整客户端共享同一个后端任务。需明确真实任务身份及交接协议。
- 兼容范围：现有原生接入针对 Linux Bash/Readline；Zsh 等不能默认承诺支持。
- 认证边界：读取既有 OpenCode 数据和配置的适配可能随版本变化；是否继续保留该方式待决定。

## 6. 决策登记

### 第一轮已确认

- 本地与远程同等重要。
- 完整图片体验可以指定支持 Kitty 图形协议的终端，其他终端降级。
- 接受独立安装定制 Tmux，与原有 Tmux 分开使用。
- 首版必须包含中文输入、图片、PDF 和 Agent；不能按研究建议将 Agent 或 PDF 排除首版。
- 同时连接行为按照 Tmux；不额外推导出协作、只读或独立布局需求。Cosmos 自有组字与草稿的客户端归属仍须明确。
- 先满足个人使用，再逐步通用化。
- terminal_agent 完全并入 Cosmos，不维护独立使用入口；现有实现暂不改动。

### 需要先澄清的运行拓扑

用户认为 SSH 连接后看到的实际都是本地内容，因此尚未回答远程安装权限问题。此处不推定用户接受远程部署。下一轮先用具体使用路径确认：Cosmos 在各主机分别运行，还是本地 Cosmos 管理 SSH 窗格，或两者组合。程序执行位置、文件所属主机与像素显示位置需要分开说明。

安装权限与依赖部署延后至运行拓扑确定后讨论，不将 root 权限作为产品能力前提。

后续每项记录：决定、理由、影响模块、未决问题与验收方式。

## 7. 实施前必须验证的假设

- 在目标终端、SSH 和目标 Tmux 组合下，图片传输、裁切、遮挡、清理及重连能否满足要求。

- 临时替换视图能否保证底层进程持续运行，并按约定恢复焦点与滚动状态。
- 目标 OpenCode 版本是否提供所需任务身份、状态与交接接口。
- 远程环境能否安装并加载所选 librime、Readline 与 PDF 依赖。

这些验证的优先级在第一轮回答后确定。尚未承诺具体技术方案或交付时间。


## 8. 第二轮已确认与接口影响

- 基本使用路径：SSH 到服务器 B 后启动 B 上的 Cosmos，会话在断线后继续保留；电脑 A 上也可独立运行 Cosmos。
- 输入法位置偏好：统一由本地 Cosmos 提供，向 SSH 窗格提交中文。此偏好与基本路径组合后，需要明确本地组件是否必须运行；目前不能假定已有本地 Cosmos 或嵌套运行。
- 中文交互：使用统一的待选缓存区，各应用中的输入体验与接口一致。缓存区的常驻性、启用方式、提交单位与普通按键直通规则待确认。
- 远程文件：同时需要远程命令 `cosmos open 路径` 和本地入口选择远程文件两种方式。后者的文件通道、认证复用和目标主机识别尚未决定，不默认本地能直接访问远程路径。
- Agent：首版接入 OpenCode，架构预留其他后端接口。
- Agent 入口：命令建议和完整 Agent 分开操作；不再将共享任务作为两个入口之间的默认要求。完整 Agent 自身任务恢复及显式上下文交接仍需设计。

### 第二轮表述的澄清

第三轮回答已取代“统一由本地 Cosmos 提供”的位置推断，也收窄了远程文件入口范围。以第 9 节为准，不要求连接端组件或 SSH 文件通道。


## 9. 第三轮确认：运行拓扑与输入语义

### 9.1 运行与文件归属

- 电脑 B 使用普通 SSH 登录电脑 A，在 A 上执行 Cosmos。会话、输入法、文件访问及扩展进程均由 A 上的 Cosmos 提供；B 负责终端显示和输入传输，不要求安装 Cosmos 配套组件。
- 本地使用也相同：在当前主机启动 Cosmos。部署权限和依赖指 Cosmos 所在主机；具体安装方式以后讨论。
- 首版不集成 SSH，不提供跨主机文件浏览。文件列表接口首先访问 Cosmos 所在主机的文件，预留未来远程协议扩展。
- 可参考或复用 Yazi 的文件列表逻辑；外部调用、借鉴设计或源码复用方式待评估，未选定实现。
- 早期“两种入口都需要”不再解释为首版需要 SSH 文件访问；命令打开与文件列表选择两种入口均针对运行主机。

### 9.2 输入法

- 输入法是统一前端，体验类似 IBus/Fcitx 一类输入法，不是普通文本的统一编辑器，也不限定只能中文。
- 只有启用输入法时才接管相应输入，退出输入法后恢复普通应用输入。
- 光标附近覆盖两行：第一行为预编辑串（如拼音），第二行为候选文字。不额外占用应用 PTY 行，不写入历史。
- 确认候选仅向绑定应用提交文字，不追加回车；应用内回车是单独操作。
- 切换窗格后，未完成组字保留在原窗格，返回后继续，新窗格使用自己的组字状态。
- “保留在原窗格”不代表多客户端共享同一个输入法上下文。候选不串客户端的既有约束仍适用；可采用客户端与窗格共同标识上下文，断开后的保留期及并发输入规则待确认。

### 9.3 命令建议基线

用户要求沿用 terminal_agent，视作小型 OpenCode 入口。核对当前源码后，基线具体为：

- 向后端传入实际目标工作目录和当前建议会话的请求/命令历史；不会默认发送窗格输出或整个项目。
- 后端在专用工作区运行，生成请求中禁用工具和执行，返回单行命令。
- 命令回填 Shell 编辑缓冲区，可继续修改，由用户在 Shell 执行。
- 小入口与完整 OpenCode 分开；不默认要求共享后端任务。现有转入完整 OpenCode 的方式以当前命令作为提示，不等价于恢复同一任务。
- 后续若希望小入口读文件、使用工具或返回解释，需要显式调整上述基线，不能由“小 OpenCode”措辞自行扩大权限。

当前仅核对源码，未进行运行验收。


## 10. 第四轮确认：输入引擎、通知、Agent 与 PDF

### 10.1 输入引擎与状态

- 用户偏好：参考 IBus 实现终端输入法前端，再接入现有 Rime；若复杂度过高，接受直接使用 librime。这是待评估的技术分支，不是已决定依赖桌面 IBus 服务。
- 配置基线为用户现有 `~/.config/ibus/rime/` 中的 rime_ice。
- 当前客户端共用输入法开关，各窗格保留自己的组字；上下文应按客户端和窗格区分。
- 首版仅预编辑与候选，不提供候选释义。
- 已只读检查本机配置：存在 rime_ice、Lua、OpenCC 和词典资源的符号链接，以及用户定制 YAML 与用户词库。迁移不能只复制单个 schema 文件，也不能默认将桌面用户词库与 Cosmos 并发共写。
- 已发现本机 ibus 可执行文件；尚未验证远程无桌面 IBus 接入能力、开发依赖或运行兼容性。

### 10.2 通知面板

- 新增“通知”呈现类型：右下角弹出，紧凑风格，高 1～2 行，按钮宽 3 字符。
- 通知作用域（客户端或当前窗格）、触发事件、按钮动作、消失规则与历史留存待确认。
- 此决定对早期“仅安静标记、不弹窗”的研究约束构成更新：允许用户要求的紧凑通知；尚未授权通知抢焦点。
- 用户尚未回答查看器退出后的滚动恢复规则；通知类型本身不能替代这项决策。

### 10.3 完整 Agent

- 使用专用窗口，不自动分屏。
- 需要获取 Cosmos 已开启 session 的信息，不能仅等同于直接运行普通 OpenCode。
- “session”的范围与可访问信息尚未确定；须区分 Tmux 会话、窗格内容、命令历史及 OpenCode 任务，不能默认全部提供。
- 命令建议仍沿用 terminal_agent 的独立入口和基线行为。

### 10.4 PDF 与 Shell

- PDF 首版除适配、缩放、移动、翻页和跳转外，必须支持文本搜索与复制。因此不能只保留页面栅格图，还需文本提取、位置映射与选择能力。
- 扫描 PDF 是否需要 OCR、复制通过何种剪贴板通道尚未确定。
- 命令建议首版完整支持 Bash，其他 Shell 后续适配。


## 11. 第五轮确认：公共接口与权限

### 11.1 Cosmos 服务与 Agent

- 完整 Agent 可发现当前 Cosmos 服务中全部 Tmux 会话、窗口、窗格、目录与运行程序；不据此扩展到其他独立 Tmux 服务或主机。
- 窗格输出按需读取，不默认将全部历史发送模型。历史范围、截断和目标标识需要在接口中明确。
- Agent 可以按用户指令操作会话与终端，沿用 OpenCode 权限确认机制。后续适配必须把 Cosmos 操作接入实际权限流程，不能仅在说明中声明权限或通过任意 PTY 注入绕开确认。
- 目录与进程信息应标明来源及不可用状态，不把无法探测的目录推断为可靠值。

### 11.2 统一通知接口

- 壳为 Mod 提供统一通知接口，而非为少数内置功能写死通知逻辑。
- 设置中提供统一界面管理通知；具体事件由相应功能发布。
- 通知不抢焦点；普通通知自动消失，需要处理的通知保留，通过快捷键进入按钮。
- 延续外观约束：右下角、高 1～2 行、按钮宽 3 字符。字符宽度按终端显示列计，按钮内容和窄窗格退化待定。
- 仍需定义通知身份、来源、级别、动作、去重、关闭、排队、历史及目标客户端。

### 11.3 查看器与恢复

- 退出查看器应回到进入前的状态。该要求至少包括原窗格、焦点和滚动位置；后台输出继续记录。精确历史位置在滚动缓冲淘汰或窗格关闭时的退化规则待定。
- 查看器适合成为独立程序，也可独立运行；通过专用接口与 Cosmos 配合获得增强体验。
- 这项独立运行要求针对查看器，不自动撤销 terminal_agent 完全并入的既定决定。
- 独立运行时不能默认承诺 Cosmos 才能提供的底层进程持续运行、视图替换和恢复能力。

### 11.4 PDF 复制范围调整

- PDF 文本搜索保留首版要求；复制到外部剪贴板的兼容层后置，先预留通信接口。
- 文本选择、内部复制内容暂存是否属于首版，需要进一步确认，不能将“复制后置”扩大解释为取消文本搜索。
- 无文字层的扫描 PDF 明确提示不可搜索文字，首版不做 OCR。


## 12. 第六轮确认：Mod、设置与统一查看器

- 内置模块使用公开接口；允许手动注册外部程序，不做插件市场。外部程序按用户安装的可信代码处理，能力声明不是系统级隔离。
- 设置采用命令面板式入口和分层子菜单，包括 Mod、显示、通知及键位。默认 Leader 为 Ctrl-B，仍保留命令入口；Ctrl-P 仅为交互类比。
- 查看器共享位图渲染层，以格式模块接入 PNG、JPG、WebP、EPS、SVG、PDF、ICO 等类型，统一打开入口。
- 多页文件需要有界缓存与预加载；缓存预算、预加载方向、任务优先级、取消与文件更新失效尚未确定。
- PDF 首版仅搜索与高亮定位；文本选择和复制预留接口。
- SSH 断开时取消该客户端组字，不终止应用或会话；同客户端不同窗格的组字仍在正常切换时保留。
- 同一服务全部客户端收到同样通知，各自在全局右下角显示。不由此推定弹出状态、已读状态或动作处理状态共享，需要继续确认。


## 13. 第七轮确认：缓存、重载与交付

- 首版必需常见位图和 PDF；EPS、SVG、ICO 可后续接入。动画先显示首帧；ICO 后续接入时自动选择尺寸，不做帧选择。
- 当前页请求优先于后台预加载；默认预加载前后各一页，快速跳转取消过时任务。
- 内存缓存结合有上限的磁盘缓存，退出后磁盘结果可复用；设置中提供清理入口。预算具体默认值由性能验证确定，不视作用户已指定。
- 文件改写后自动重载，尽量保留页码、缩放与位置。需要避免读取尚未写完的文件；失败不得丢失现有可用视图。页数减少时采用明确的有效页回退规则。
- 缓存必须区分源文件版本、页面、渲染参数与渲染后端版本，不能仅按文件路径复用；过时异步结果不能覆盖新文件或新页请求。
- 通知动作在服务级处理并同步状态，各客户端不重复执行同一已处理动作；普通关闭只影响当前客户端。具体幂等与竞态机制由接口设计落实。
- 完整 Agent 允许用户显式创建和选择多个窗口，各窗口绑定各自任务。自动复用固定单窗口不作为默认行为。
- 安装优先提供可下载解压的构建包，减少目标主机依赖；目标系统、架构与运行库基线待确认。此偏好不等于已经保证完全静态或零依赖。


## 14. 第八轮确认：平台与交互范围

- 首版发布目标 Linux x86_64，其他系统与架构后续支持；具体运行库基线待技术评估。
- 命令面板默认只显示操作，设置和 Mod 进入相应子菜单；不混合全局文件、会话及任务搜索结果。
- 文件入口集成 Yazi 的部分功能，需改造 UI、布局、快捷键，并通过 Cosmos 接口协作；不是原样启动 Yazi。具体功能子集仍需最后确认。
- 查看器首版支持滚轮翻页或缩放、拖动平移；所有功能同时提供键盘操作。
- 首版提供深色和浅色主题，所有模块共享角色调色板。
- 输入法先通过 Leader 后的按键切换，具体后续按键在原型阶段确认，不先占用 Ctrl-Space 等应用键位。
- 默认简洁状态栏，可在设置隐藏。
- 下一步继续少量必要提问，随后整理模块、接口、目录结构与分阶段验收；暂不实现，也不提前制作运行原型。


## 15. 第九轮确认与设计输出

- 文件管理保留 Yazi 现有能力，统一交互，取代早期“仅部分功能”的范围表述。
- 提供专用文件窗口和可折叠左侧 panel。Panel 顶部目录，上方主要区域显示目标窗格目录内容，下方显示选中文件预览；未选择不预览。
- 窗口树保留按真实布局显示的内容预览，去掉活动热度。
- 首版需要跨本服务全部窗格搜索仍保留的终端输出。
- 无法精确恢复现场时回到最近可用状态并通知。
- 再次明确运行拓扑：普通 SSH 登录后启动远程 Cosmos，类似 Tmux/Screen。断线不结束查看器、Agent 或会话，服务仍在即可重连；不要求连接电脑运行本地组件。
- 不承诺所有服务进程停止或主机重启后恢复原应用进程；这与连接重建不同。

整理后的实施方案见 [实施方案-v0.1](实施方案-v0.1.md)，包含模块、接口、目录、迁移与分阶段验收。技术选型标为建议或待验证，未进入实现。


## 最新架构澄清与 panel 修复

用户明确 Cosmos 应自行实现大部分逻辑，同时复用 Tmux 稳定部分。此决定覆盖先前“定制 Tmux 为主体”的路线，见 [架构边界修订](架构边界修订.md)。

panel 闪退已定位为旧协调服务协议 1.0 与新客户端接口不匹配；增加能力预检与持久显示错误，更新实际旧服务时核对保留了所有终端对象。
