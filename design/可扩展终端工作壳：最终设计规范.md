# 可扩展终端工作壳 · 设计定稿

## 1. 产品定位与设计哲学

**以 Tmux 为核心的可扩展终端工作壳：默认保持终端的简洁，通过 Mod 提供中文输入、Agent、图片与 PDF 等能力。**

| 原则 | 约束 |
|---|---|
| 壳提供秩序，Mod 提供能力 | 壳统一空间、焦点、呈现与生命周期；不统一所有应用的内部操作 |
| 默认就是终端 | 不常驻 AI、日志、预览、菜单；安装能力不等于增加 UI |
| 用户掌控空间 | 沿用 Tmux 会话、窗口、窗格、放大逻辑；不自动分屏或重排 |
| 只画必要元素 | 能由位置、边界表达的，不重复写文字；细节按需查看 |
| 常规靠秩序，后果靠说明 | 常规状态安静呈现；发送对象、权限、破坏性操作必须明确 |
| 替换显示，不破坏现场 | 查看图片/PDF 临时替换当前窗格视图；退出恢复原现场 |
| 临时的是界面，不一定是工作 | 隐藏界面、取消输入、停止任务分别处理 |
| 组合优先于原创 | 新增贡献是能力之间一致、可靠的交互，而非重新发明基础工具 |

## 2. 最终架构

**单一屏幕管理者：Tmux 及其壳扩展。独立 Mod 在窗格或受控呈现区运行，不任意重绘外层终端。**

| 层 / 模块 | 职责 | 边界 |
|---|---|---|
| 本地终端 | 字符与像素显示、键盘事件、终端能力响应 | 完整图像体验需要兼容的 Kitty 图形协议实现 |
| SSH / PTY | 传输终端输入、输出及控制序列 | 不依赖本地可访问远程文件 |
| Tmux 核心 | 会话、窗口、窗格、PTY、终端解析、布局、attach/detach | 保留原有工作模型，尽量减少侵入式修改 |
| 壳扩展 | 底部输入、受控浮层、临时视图、焦点路由、命令入口 | 统一呈现与返回规则，不接管应用内部语法 |
| 中文输入模块 | librime 组字、候选、提交文本 | 只向绑定的输入目标提交；支持明确直通 |
| 图像显示模块 | Kitty 数据传输、占位显示、可见区域、清理与恢复 | 协议透传不等于完成图片状态管理 |
| PDF 模块 | 页面栅格化、分页、缩放、缓存 | 复用图像后端，不另建显示系统 |
| Agent 适配 | 连接 OpenCode、关联任务、提交明确上下文、状态通知 | 保留完整客户端，不复制第二套 Agent 状态 |
| Mod 管理 | 安装、启停、操作注册、兼容检查、权限与进程管理 | 不要求所有模块使用同一语言或链接进核心 |

| 状态归属 | 最终要求 |
|---|---|
| 会话与任务 | 独立于临时显示持续存在 |
| 客户端交互 | 焦点、组字、浮层、未提交草稿不被其他客户端干扰 |
| 本地图片资源 | 按客户端能力与缓存管理；重新连接时可重传、重建 |
| 关联对象 | 终端、文件、Agent 使用稳定标识，不只依赖易变化的窗格编号 |

## 3. 空间与交互模型

| 区域 | 用途 | 默认表现 |
|---|---|---|
| 主区 | Shell、编辑器、Agent、其他完整 TUI | 沿用 Tmux 布局，无专属功能预留位 |
| 底部交互区 | 组字、搜索、AI 短输入、壳命令 | 按需出现；结束后收起 |
| 状态栏 | 工作位置、必要模式、待处理标记 | 短、小、可隐藏；不重复焦点信息 |
| 悬浮区 | 候选、补全、搜索结果、短预览、帮助 | 就地辅助；出现不默认抢焦点 |
| 临时替换视图 | 图片与 PDF 查看 | 只替换当前窗格显示，不终止底下进程 |

| 输入规则 | 要求 |
|---|---|
| 内容操作 | 默认按键交给当前应用 |
| 壳操作 | 通过可配置 Leader 或命令入口明确进入 |
| 中文组字 | 预编辑与候选属于原输入目标，不视为新窗口 |
| 辅助交互 | 明确接管所需按键，关闭后返回来源 |
| 操作入口 | 同一动作同时可由命令与快捷键调用，不维护两套行为 |
| 退出规则 | 壳级取消逐层返回；不重定义 Vim、Yazi 等应用内部退出键 |
| 切换输入目标 | 不误提交；草稿与组字具有确定的保留、恢复或显式取消规则 |

## 4. UI 设计规范

| 项目 | 规范 |
|---|---|
| 视觉基调 | 终端优先、低装饰、统一配色；不用动画和拟物效果证明精致 |
| 元素准入 | 元素必须解决当前感知或操作问题；不能只为展示功能存在 |
| 边框 | 沿用已有窗格边界；避免框中框、重复标题与多层卡片 |
| 焦点 | 使用一致的边界或样式；关键差异不只依赖颜色 |
| 状态文字 | 显示异常、歧义和后果；常规状态尽量由位置与样式表达 |
| 帮助 | 主动调用查看；不永久铺满快捷键提示 |
| 后台提醒 | 安静标记、主动查看；不抢焦点、不自动开窗 |
| 小屏处理 | 裁减低优先级信息、分页或滚动；不自动合并分屏 |
| 大屏处理 | 尊重用户布局；不因空间增加而自动展示更多模块 |
| 底部展开 | 采用统一呈现策略；候选变化不反复改变 PTY 尺寸 |
| 字符处理 | 正确处理中文宽度、组合字符与截断；不能只按字节计数 |
| Mod 风格 | 使用壳的配色、边界、提示和返回规范；无独立“插件桌面” |

### 图片与 PDF 查看

| 项目 | 图片 | PDF |
|---|---|---|
| 打开 | 临时替换当前窗格视图 | 同左，显示当前页 |
| 默认显示 | 保持比例、完整适配 | 页面适配可用区域 |
| 常驻 UI | 不设工具栏、属性区、额外边框 | 仅必要的页码，如 `3 / 18` |
| 基本操作 | 缩放、移动、退出、帮助 | 另有翻页与页码跳转 |
| 放大窗格 | 使用已有 Tmux 放大操作 | 同左 |
| 退出 | 恢复终端显示、焦点与滚动位置 | 同左 |
| 底下任务 | 继续运行，输出正常记录 | 同左 |
| 非目标 | 不默认建立图片管理桌面 | 不默认建立缩略图、目录、菜单三栏阅读器 |

## 5. 最终能力要求

| 能力 | 最终目标 |
|---|---|
| 终端复用 | 保留 Tmux 的持续会话、分屏、焦点切换、放大与重连体验 |
| 中文输入 | 无桌面环境可用；支持 Rime 配置、候选翻页、组字与提交；显式切换直通 |
| 远程图片 | 本地兼容终端经 SSH、Tmux 正常显示；远程直接传图像数据 |
| 图像边界 | 正确处理窗格裁切、遮挡、缩放、窗口切换、清理与重新显示 |
| PDF | 页面栅格化、分页、页码跳转、缩放、移动与受限缓存 |
| Agent | 完整客户端与底部快捷输入关联同一任务；权限、运行、等待确认状态一致 |
| 上下文 | 可见、可检查、可移除；不默认发送全部历史或读取整个项目 |
| 命令建议 | 预览、送入指定终端与实际执行分离；不把粘贴当作安全确认 |
| 搜索 | 底部查询、按需候选；浏览不提交，确认才跳转 |
| Mods | 按需安装启用；操作可发现；明确权限、兼容性、生命周期 |
| 多客户端 | 独立处理尺寸、能力、交互焦点和图像资源；不串输入、不串组字 |
| 能力降级 | 不支持像素图像时提供明确提示或字符预览，不破坏终端体验 |

## 6. 软件设计要求

| 维度 | 要求 |
|---|---|
| 核心边界 | 保留成熟终端解析与复用机制；不把 PTY 输出当普通文本重新拼装 |
| 绘制所有权 | 外层终端由单一管理者控制；Mod 通过受控区域或独立窗格呈现 |
| 状态模型 | 内容身份、显示状态、输入目标分离；隐藏与销毁分别建模 |
| Mod 接口 | 定义命令、呈现、生命周期、权限与版本；外部进程使用明确 IPC |
| 性能敏感路径 | 输入法等低延迟模块可内置；不强迫所有能力动态插件化 |
| 故障隔离 | Mod 崩溃不拖垮会话；恢复焦点、终端模式与临时显示 |
| 图形资源 | 有界缓存、唯一标识、客户端隔离、重传与清理；避免切换残影 |
| 性能 | 空闲时低开销；按需重绘；预览解码、PDF 栅格化不阻塞输入 |
| 安全 | 明确文件、网络与执行权限；屏蔽不可信终端控制内容；密钥不进入日志或上下文 |
| 配置 | 一个壳配置入口，各 Mod 独立命名空间；默认可用，避免必填配置墙 |
| 可维护性 | 上游修改与自有扩展分离；固定依赖版本，记录补丁与兼容矩阵 |
| 验证 | 覆盖 SSH、嵌套复用、不同终端、resize、attach/detach、多客户端及异常退出 |
| 许可证 | 区分设计参考、协议实现、外部调用与源码复制；逐项审查分发义务 |

**最终体验标准：平时看见终端，查看时看见内容，需要帮助时才出现辅助；离开辅助后，工作现场仍然准确地在那里。**
