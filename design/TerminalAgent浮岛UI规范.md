# terminal_agent 浮岛 UI 设计规范

日期：2026-10-22。状态：设计规范，尚不代表运行代码已按本文实现。

用户已选择方案 01「浮岛」。本文将外观草图细化为实现默认值；尺寸、时序及键位是本文确定的实现约定，不应描述为用户逐项确认的参数。本文只约束 Cosmos 中的命令助手呈现，不修改独立 terminal_agent，也不改变完整 Agent 的界面。

## 1. 必须保持的行为

- Shell 命令始终由现有 Readline 适配器在原位置更新和编辑。不能改成复制按钮、发送按键粘贴、聊天消息或新建终端输出行。
- 下方浮岛编辑的是「给助手的请求」，上方 Shell 命令行显示当前命令；不在浮岛里再放一个命令编辑框。
- 沿用原控制器：请求框 Enter 生成；成功返回 `update`，原位替换 Shell 命令，不附带回车、不执行，随后恢复浮岛请求编辑。已有请求历史和未提交草稿保留。
- Tab 返回 Bash 原生编辑。Bash 中 Enter 执行命令；浮岛中的运行动作返回现有 `run` 结果。更新、返回编辑、运行是三个不同动作，UI 不得混用。
- 不改变后端权限、模型配置、请求上下文或 OpenCode 行为。
- 浮岛显示、消失和按钮展开不得改变 PTY 尺寸、触发 Shell 换行、增加 PS1 或移动终端滚动位置。

## 2. 视觉结构

常态只包含一块紧凑色面，按内容决定宽度，不铺满窗格。无外边框、阴影、标题、分隔线、三角接头、固定快捷键说明或第二层卡片。

下述方括号及竖线只是几何标注，不是实际显示字符：

```text
Shell 原位命令：  $ find . -type f -size +100M

常态：           [ 空格 状态点 空格 请求编辑区 空格 ]
动作可见：       [ 空格 状态点 空格 请求编辑区 空格 ] 空格 [ a ][ × ][ ↵ ]
```

输入面和操作簇共用一个布局对象，操作簇可使用同一背景；中间仅一个字符格的透明间隔。三个按钮相邻，没有框和分隔符。输入面不是全宽底栏。

默认图标：状态点 `●`，Agent `a`，关闭 `×`，运行 `↵`。全部要求占一个字符格，不依赖 Nerd Font、emoji 或 Kitty 图片。主题可替换图标，但替代字符必须通过实际终端字符宽度检查；不满足时回退默认值。

## 3. 尺寸与宽度算法

所有长度以终端字符格为单位；中文、组合字符和宽字符必须由统一的 grapheme/cell-width 逻辑计算，禁止直接使用字符串长度。输入光标不得落在宽字符的第二格或组合字符中间。

定义：

- `P`：源窗格内容矩形，不含分割线及全局状态栏。
- 当 `P.width >= 20`，左右各预留 2 格；否则不预留外侧空白。
- `A = min(88, P.width - 左外侧空白 - 右外侧空白)`，即浮岛总宽度上限。
- `T`：当前请求的显示格数。空请求用本节占位文本的显示格数计算。
- 输入区理想宽度 `E0 = clamp(T + 2, 24, 72)`。
- 常态固定开销 4 格：左内边距 1、状态点 1、间隔 1、右内边距 1。
- 常态总宽 `W0 = min(A, E0 + 4)`；实际输入区宽 `E = W0 - 4`。
- 操作簇额外占用 10 格：外部间隔 1、三个按钮各 3 格。展开总宽 `W1 = min(A, W0 + 10)`，展开后的输入区宽 `E1 = W1 - 14`。
- 只有 `E1 >= 12` 才允许显示操作簇。优先向右增长，右侧空间不足才缩小输入视口；不得丢弃或截断实际请求内容。

常态高度严格 1 行。除错误详情外不增加第二行。操作簇显隐不改变高度。

空请求占位文本为 `描述命令…`，使用弱文字色；占位文本不是输入内容，不进入历史，也不随动画闪烁。

宽度增长在新的内容超过当前输入容量时立即发生。内容缩短后等待 250 ms 无编辑输入再收缩；该定时器每次编辑重置。恢复历史时直接重算。操作簇的显示与隐藏立即完成几何切换，不逐格扩张、不滑动文字。缩放窗格时立即裁剪到新边界，不等待收缩定时器。

## 4. 定位与保护区域

浮岛归属 `insert/cover line`，绑定稳定的源 pane ID。横坐标为源窗格左边加本节定义的外侧空白，不跟随输入光标左右漂移。

原生适配器需要提供当前 Readline 命令的完整显示范围 `source_command_rect`，包括多行 PS1 和命令折行。仅使用 `cursor_y + 1` 不足以确定安全位置：光标可能位于多行命令中间。若无法取得有效范围，不打开活动浮岛，返回原生编辑并通知「无法定位原位命令区域」；不得通过猜测位置覆盖命令。窗口缩放后，旧范围立即失效，取得新范围前暂停活动浮岛绘制。

位置按以下顺序选择：

1. 源命令完整显示范围下一行，能容纳浮岛时使用该位置。
2. 下方空间不足时放在源命令完整范围上方，并保持 1 行；错误展开需要 2 行时按两行重新计算。
3. 上下均无安全行时不覆盖命令、不跨越分割线、不改 PTY 大小；关闭活动浮岛、返回原生编辑，并通过通知说明空间不足。请求草稿保留。

浮岛允许暂时覆盖源窗格的其他终端输出，但必须透明保留矩形外的内容。关闭后恢复被覆盖的最新终端画面，而非旧截图。上方命令内容、输入光标、其他窗格、全局状态栏及通知均不得被浮岛覆盖。

主请求框获得编辑焦点时，只显示其输入光标，隐藏背后 Shell 的物理光标。返回原生编辑时恢复 Shell 光标及应用声明的形状/闪烁状态，不能同时出现两个可编辑光标。

## 5. 状态与转换

浮岛展示状态由原控制器及原生桥接结果推导，不能在 UI 内维护第二套生成任务或命令历史。

### 5.1 `editing`：编辑请求

显示静态 `●` 和请求输入。按钮默认隐藏。Enter 对非空请求启动生成；空请求不发起调用，也不报错。上/下键沿用原请求历史，越过最新历史时恢复未提交草稿及其光标。Esc / Ctrl-C / Ctrl-Q 关闭浮岛；Ctrl-G 沿用完整 Agent 入口，与 `a` 按钮同义。

### 5.2 `generating`：生成中

保留请求文字和当前 Shell 命令；请求框暂时只读，光标隐藏，状态点做呼吸动画。不把模型 token 流或工具日志铺到浮岛中，不显示进度百分比。

生成期间禁止重复提交、运行和转到完整 Agent；文本输入、历史键和 Tab 均不改变请求或转交焦点，Leader 帮助和动作模式仍可使用。Esc / Ctrl-C / Ctrl-Q 或关闭动作取消本次生成并关闭浮岛，保留草稿，Shell 命令不因取消而执行。取消后的迟到结果必须按请求版本丢弃。

### 5.3 `ready`：已生成、待后续操作

收到成功结果后执行现有 `update` 协议，原位更新 Shell 命令，停止呼吸动画；不得追加 Enter。请求框按原控制器行为清空，显示占位文本，允许继续输入修订请求。

状态点短暂显示 `✓` 600 ms，随后恢复静态 `●`。正常完成不主动展开按钮、不弹通知、不显示重复命令预览。最后一次请求仍存在于原历史中，可以上键恢复。

原生桥接在 `update` 后关闭并重新创建 presenter 时，UI 需要携带同一交互 ID 和完成时间戳，恢复当前位置/宽度与完成提示；不能闪回全宽栏、重复进入动画或重启同一生成请求。

### 5.4 `error`：可恢复错误

保留请求、光标和当前 Shell 命令；状态字符改为静态 `!`。Enter 重试当前请求，不自动重试。

有空间时在输入面下方增加一行同宽错误摘要，最多两行总高度；摘要左内边距 1，无标题/外框/按钮，按格宽省略。无安全的第二行时保留单行浮岛，并用通知显示摘要。完整诊断进日志；不得把密钥、终端正文或完整模型请求写入日志。

下一次有效编辑清除错误摘要并回到 `editing`。错误消失后立即恢复 1 行布局和安全定位。

### 5.5 `native_edit`：返回 Bash 原位编辑

Tab 返回现有 `edit` 结果，浮岛收起，输入焦点交回 Readline。原先约定的 bottom powerline 可保留紧凑、静态的最近请求提示；它不是第二个输入框，不显示浮岛操作簇，也不参加呼吸动画。其显隐仍不得改变 PTY 尺寸。

### 5.6 `closed`：关闭

Esc 关闭、运行命令、进入完整 Agent、源窗格消失、客户端分离等结束活动呈现，移除命中区域和动画定时器，恢复底层最新画面。客户端断开不执行任何命令。

## 6. 操作簇显隐和焦点

操作簇只在下列条件显示：

- 鼠标连续停留在浮岛内至少 180 ms。
- 用户按 `Leader .` 显式进入浮岛操作模式。

鼠标离开输入面和操作簇的联合命中区域 350 ms 后隐藏；跨越二者间的一格空白不视为离开。输入框接收到一次实际文本编辑或历史切换时立即隐藏鼠标触发的操作簇。鼠标不动不会把刚隐藏的操作簇再次展开，需重新移动或重新进入。

鼠标展开不抢输入焦点、不移动光标。按钮 hover 只改变该按钮，不改变其他按钮或整块浮岛的颜色。

`Leader .` 是本规范新增的上下文操作，在活动浮岛中生效。进入后保存请求光标，显示操作簇，焦点优先给可用的运行按钮；没有可运行命令或正在生成时给关闭按钮。左右键循环选择可用动作，Enter 执行选中的动作，Esc 仅退出操作模式、回到请求输入，不关闭浮岛。Tab 仍保持既有「返回 Bash 原生编辑」行为，不借用 Tab 循环按钮。

因宽度不足无法容纳操作簇时，`Leader .` 打开 Cosmos 紧凑动作菜单，不挤占请求区、不绘制截断按钮；菜单关闭后恢复浮岛。动作菜单遵循统一 pop window 和帮助规范，不新增另一套菜单样式。

按钮具体行为：

- `a`：进入现有完整 Agent 入口，传递已有控制器约定的上下文；不执行 Shell 命令。生成中禁用。
- `×`：关闭浮岛；生成中先取消任务。保留草稿和已有原位命令。
- `↵`：运行当前 Shell 命令，返回现有 `run` 结果并收起浮岛。命令为空或生成中禁用。它不等同于请求框 Enter，不是「只替换不执行」按钮。

按钮各占 3 格，图标居中，整块 3×1 区域均可点击；点击在抬起时生效，且按下与抬起必须命中同一动作。禁用动作仍画出图标，但不能命中或获得操作焦点。

`Leader ?` 展示当前上下文帮助，包括生成、原生编辑、动作模式、历史和取消。帮助中明确将 `↵` 标为「运行当前命令」，不使用含糊的「确认」。默认不常驻按钮文字说明或快捷键标签。

Leader 处理必须忽略独立 Shift / Ctrl / Alt 和锁定键事件；它们不消费待处理前缀，不传给子 PTY。保留 Kitty 扩展键盘协议与普通终端的共同语义。

## 7. 主题角色与图标状态

全部颜色来自 Cosmos 主题解析器。模块禁止持有固定 RGB 值或独立主题配置。

使用如下语义 token，解析器统一负责回退：

- `assistant.surface`：浮岛及静态按钮背景；默认在 `base` 与 `acc` 间按 94% / 6% 混合。
- `assistant.text`：请求文字，默认 `fg`。
- `assistant.muted`：占位文本、闲置按钮、静态状态点，默认 `mute`。
- `assistant.accent`：生成点和 hover 图标，默认 `acc`。
- `assistant.accentStrong`：呼吸峰值及活动按钮背景，默认 `accl`。
- `assistant.onAccent`：活动按钮图标，默认 `on`。
- `assistant.success` / `assistant.error`：优先采用主题已有对应语义角色；缺失时回退 `acc` / `accl`，同时用 `✓` / `!` 区分语义。

上面的 token 是本规范要求的呈现接口，不能因为定义了名称便假定主题系统已提供这些字段。回退映射必须在统一主题解析层实现，不能在每个控件内复制。

选中/hover 按钮使用活动背景和 `onAccent` 图标；仅有 focus 时增加图标加粗，不加框线。禁用图标使用 muted，背景保持 surface，不能将整块按钮设为近乎透明以至字符不可见。

明暗主题都应形成可辨别的浮岛色面。浮岛与源终端之间若过于接近，主题解析器可提高混合权重至 12%；不得用加边框弥补。常规文字对比度目标至少 4.5:1，状态/禁用图标至少 3:1；状态不能只靠色相区分。

## 8. 动画的精确定义

只保留有业务含义的动态效果：

1. 生成点：字符固定为 `●`，不轮换字符、不旋转。周期 1400 ms，颜色插值参数 `u = (1 - cos(2πt / 1400ms)) / 2`，在 accent 与 accentStrong 之间呼吸。最多 12 fps，只重绘状态点所在的 1 格。
2. 按钮 hover/focus：颜色过渡 120 ms，最多 12 fps，只重绘目标按钮的 3 格。失焦后回到静态色；不做大小、位置或图标跳动。
3. 完成提示：`✓` 保持 600 ms 后切回静态点；没有持续闪烁或成功弹跳。

打开/关闭浮岛、按钮簇显隐和宽度调整均为一次几何更新，不做位移动画、逐字揭示、渐进展开或整行渐隐。请求文字始终静止。输入光标使用已有编辑器闪烁机制，不用全屏刷新模拟。

Cosmos 开启减少动画时，生成点为静态 accent 色 `●`，按钮颜色立即切换；完成提示仍静态显示 600 ms。失焦、遮挡、源 pane 不可见或客户端分离时停止动画调度；恢复后按单调时钟计算当前状态，不补播丢失帧。

## 9. 长文本、窄窗格和鼠标

- 请求永远单行呈现；长请求水平滚动，始终让插入点可见。对请求框粘贴的 CRLF / CR / LF 统一转换为单个空格，其他字符保持原样；不能因粘贴增加浮岛高度或触发生成。该规则只适用于请求框，不改变 Shell 命令字符串和原生编辑行为。
- 不在输入框内部增加省略号、滚动箭头或字符计数来挤占宽度；滚动不改变实际文本。
- `A >= 16` 使用正常结构。`6 <= A < 16` 保留 4 格固定结构，将剩余宽度全部给输入区，按钮只能通过动作菜单使用。
- `1 <= A < 6` 仅显示最多 A 格的编辑视口，省略状态点和内边距；仍支持生成、取消、历史及动作菜单。无可用安全行时按定位规则退回原生编辑。
- 鼠标在输入面内点击/拖动沿用统一编辑器的插入点与选择行为；背景空白不捕获其他窗格的点击。
- 鼠标滚轮在浮岛内不切换请求历史、不滚动背后终端；请求历史只通过上/下键改变。
- 窗格切焦点或其他 UI 获得输入焦点时，不继续把按键送给浮岛。按现有模态规则恢复/关闭，必须先停止本地绘制及命中处理；不得跨 pane 提交结果。

## 10. 实现接口与职责

模型、历史与原生命令更新继续归现有 terminal_agent 控制器和桥接器。Cosmos presenter 负责浮岛布局、状态映射和输入路由。可采用自绘字符组件，不强制继承 Textual Input/Button 的盒子样式。

推荐将渲染输入拆成可测试的数据，不把主题、控制器调用和写屏混在控件中：

```text
IslandModel
  interaction_id, source_pane_id, request_version
  phase, request_text, request_cursor, has_command, error_summary
  source_command_rect, pane_rect, theme_roles, reduced_motion

IslandViewState
  measured_width, pending_shrink_deadline
  actions_visible, action_focus, hover_deadlines
  completion_timestamp, generation_started_at

IslandLayout
  input_surface_rect, status_rect?, editor_rect
  action_rects[], error_rect?, union_hit_rect

Presenter result
  cell_runs / dirty_rects
  cursor_position / cursor_visibility
  hit_regions(action_id, enabled)
```

单一 compositor/driver 负责最终写屏；组件不能直接 stdout 输出 ANSI，也不能启动 prompt_toolkit 第二套输出循环。文字宽度、裁剪、焦点、主题、动作帮助和命中必须使用 Cosmos 的共享接口。

现有可复用位置：`python/cosmos_tui/assistant.py`、`primitives.py`、`chrome.py`、`agent_bridge.py` 和原 `terminal_agent` 控制器/Readline 桥接。`source_command_rect`、完成状态连续性、上述主题 token、动作模式和收缩定时器属于待实现接口，不能直接假定现有代码已经具备。

UI-only 动画帧不重复请求 Tmux snapshot、不触发后端 RPC、不再次执行模型生成。生成结果必须校验交互 ID、pane ID 和请求版本；失效回调不能改变后来活动的窗格或覆盖新的草稿。

## 11. 验收标准

1. 空请求、短请求、中文长请求分别显示正确宽度；不出现全宽底栏、边框、分隔符或常驻说明。长输入、组合字符、历史恢复与光标均不被裁断。
2. 宽度为 88、40、24、12、4 格及源命令折行场景符合公式；屏幕上下边缘、分屏和窗口缩放不越界、不覆盖原位命令。操作簇不足 12 格输入空间时使用菜单降级。
3. 真实 Bash 中至少 12 次打开/关闭及 Tab 往返，PS1 和原命令不递增；PTY rows/cols 和滚动位置不因浮岛显隐改变。
