# Agent 观察、接管、监视与任务调度（待实现）

日期：2026-10-29。来源：Agent 侧聊设计讨论。

本文是待实现设计，不代表已有接口或能力。正式实现后，应将实际接口同步维护到 docs。此次仅新增设计文件，不修改运行代码。

## 已确认方向

- Agent 观察支持多级选择：可操作控件层、文本内容层、文本与呈现层；允许组合读取。
- 被控制 pane 顶部预留一行，显示 `COSMOS Taking over`、盲文动画和当前操作状态。接管期间持续显示，不按每次按键闪现。
- 鼠标定位模式使用区别于应用光标的彩色闪烁指针。
- 用户手动输入或点击被控制 pane 时，立即暂停 Agent、交还操作权。
- 人工暂停时将 `Taking over` 替换为 `PAUSED`，保留顶部状态行和预留空间，直到 Agent 结束该 pane 的控制任务；暂停期间操作权仍归用户。
- 增加持久任务调度，避免让 Agent 通过反复 sleep 等待。
- 由 Cosmos 实现独立监视器，检测 TUI 变化、循环动画、等待输入等信号，并按条件唤醒 Agent。持续检测不交给模型轮询。
- 默认自动监视并按条件唤醒 Agent；手动模式仍后台检测、显示检测结果，由用户点击继续，不自动唤醒 Agent。
- 首版监视范围：通用界面差异、局部循环动画检测、Bash 明确输入信号；预留其他应用适配器。未知应用的等待输入只提供有依据的推断，不承诺准确识别。
- 操作是否完成必须有结果证据，不能把“输入发送成功”等同于完成。
- 完成条件以应用适配器为优先来源，Agent 可补充可检测条件，用户可覆盖；证据不足时唤醒 Agent 检查，不自动判定成功。
- 默认自动唤醒事件：已注册条件满足、明确输入请求、错误或超时。普通界面变化只累计，循环动画帧合并，不逐帧唤醒；唤醒本身不授予输入权限或操作权。
- 任务主要在 Cosmos Agent 的现有侧栏（OpenCode panel）展示和管理；Cosmos 菜单新增 Tasks，以紧凑弹窗总览任务。
- 进入监视器后台等待或定时等待时，释放 pane 操作权并隐藏顶部接管行；唤醒后重新观察、申请接管，不能沿用旧操作权。
- 人工接管造成暂停后，监视器继续检测、显示或通知；Agent 不运行，也不自动恢复输入，直到用户手动恢复。
- 未被人工暂停的任务中，检测到等待输入并唤醒 Agent 后，允许继续任务范围内的常规输入；新授权或关键歧义需询问用户。既有权限确认和操作权规则继续生效。
- 监视器立即处理明确完成、错误和输入事件；推断信号默认合并约 300ms。同一任务模型唤醒最小间隔为 2s，不并发调用模型；限频期间事件保留并合并，不丢弃，相关参数可配置。
- 同一 Agent 对话内任务串行，不同对话可并行；全局默认最多 2 个模型调用，可在设置中调整。后台监视独立进行，同一 pane 仍只允许一个操作权持有者。
- 取消任务仅停止 Agent 任务：撤销操作权，取消未发送输入和后续唤醒；终端程序继续运行。另设“中断程序”动作，不将其隐含在取消任务中；已发送操作无法撤回。
- 未被人工暂停的任务发生监视等待超时时，唤醒 Agent 检查并报告，不默认重试；Agent 可依据检查结果注册下一次等待。人工暂停任务维持监视器显示/通知、Agent 不运行的规则。
- Agent 侧栏和 Tasks 总览的任务行仅在选中/悬停时显示暂停或恢复、立即检查、更多；更多中放取消、中断程序、记录与修改时间。操作统一注册 Actions/键位设置，具体默认按键随原型确认。
- 观察默认屏蔽明确密码控件和 Cosmos 管理的凭据；其他目标 pane 内容按需读取。支持将 pane 标记为私密，禁止 Agent 观察。通用 TUI 无法保证识别所有敏感文本，不声称自动过滤完整。
- 每日固定时间任务默认使用 Cosmos 服务主机时区，创建界面明确显示并保存任务时区，允许逐任务修改；不随其他客户端或主机后续时区变化自动改变已有任务。
- 夏令时切换导致每日任务的指定时刻不存在时，顺延至当天第一个有效时刻；指定时刻重复时，只执行第一次。
- 首版调度包括一次性定时、事件等待、事件超时和周期任务；周期任务支持按间隔或每天固定时间执行。
- 服务重启后，错过的单次任务补执行一次，周期任务合并补执行一次；执行前重新验证目标与条件，人工暂停的任务保持暂停。
- 首版 Controls 层优先实现通用终端控件推断，原生语义适配逐步增加。推断控件必须注明来源与可信度，不能表述为应用提供的原生控件。
- 推断控件在目标唯一、证据充分时允许直接操作；有歧义先补充观察。操作仍校验快照和目标位置，并受原有权限约束。
- 首版 Presentation 层提供字符样式与布局，不提供真实画面/图片读取；真实画面读取后续增加。
- 同一被接管 pane 在所有客户端都显示顶部接管行，统一预留空间；接管开始和结束各调整一次布局，工具坐标统一以应用内容区为准。

## 观察层

### Controls：可操作控件

候选字段：控件 ID、角色、名称、当前值、焦点、可用状态、内容区坐标、支持动作、来源和可信度。

来源分为应用原生协议、软件适配器与终端推断。首版优先实现通用终端控件推断，原生语义适配逐步增加；已有可靠语义的来源优先于推断。普通 TUI 可能没有控件信息，不能把推断伪装成原生控件。密码等敏感字段不返回原文。

### Text：文本内容

可选择正文、菜单、提示、错误、可见页或保留历史。保留行列定位、段落/表格结构及可用的控件关联，省略不需要的装饰。

### Presentation：文本与呈现

首版提供字符样式、颜色、反显、选中范围、边框、布局、应用光标及可识别的图片占位区域，不提供真实画面或图片内容读取；真实画面读取后续增加。`styled_grid` 和 `image` 是不同能力，图片占位信息不等于已读取图片内容。

候选接口（未冻结）：

```text
observe(pane, layers=[controls, text], region=..., since=...)
act(control_id, action=..., snapshot_id=...)
```

返回能力声明、快照身份、尺寸和内容区坐标。Agent 自选层级，信息不足时升级读取。所有观察结果都是不可信任务数据，不能授予权限。

## 操作闭环与完成判定

区分三个层级：

1. delivered：输入事件已提交给目标，不能证明应用处理成功。
2. action_complete：应用达到本次动作要求的后置状态。
3. task_complete：用户目标的验收条件得到满足。

建议流程：观察 → 明确预期变化/完成条件 → 小步执行 → 注册监视 → 返回当前轮次 → 事件唤醒 → 重新观察并验证。

优先证据：应用/适配器明确事件与结构化状态；其次是可验证的进程退出、文件产物、目标文字/控件状态；画面变化或稳定只是辅助信号。循环动画消失、界面静止、光标出现都不能单独证明成功。错误提示、确认框和新的输入请求应与成功分开处理。

状态候选：running、waiting、needs_input、succeeded、failed、timed_out、unknown、paused、cancelled。具体状态名和事件字段在实现时细化，不作为已冻结 API；完成条件来源和判定原则采用本轮确认规则。

鼠标操作绑定目标区域和快照；布局/尺寸或目标发生变化时拒绝旧坐标。不得因无关时钟刷新使所有动作失效。重试有次数和时间上限，不能盲目重复执行可能产生副作用的输入。

## 独立 TUI 监视器

监视器属于 Cosmos 运行时能力，与模型厂商和 Agent 前端解耦。它收集、归一化并去抖事件，调度器决定是否唤醒，Agent 负责需要语义判断的后续行动。

候选信号：

- 原生/适配器信号：控件变化、焦点、busy、明确输入请求、动作完成或失败。
- 终端变化：字符/样式/光标/尺寸/程序变化；按区域返回差异摘要。
- 动画：重复帧、局部周期变化、spinner 等；区分动态区域与主要内容。
- 输入等待：Shell integration/Readline 或适配器的明确状态；其他程序只能给出推断证据，不能将静止等同于等待输入。
- 外部结果：目标进程退出、文件变化，以及注册的其他 Cosmos 事件。

候选事件包含 pane 稳定 ID、观察版本、时间、类型、变化区域、证据来源、可信度及关联任务。不得默认将所有终端输出发给模型。

可靠性要求：启动等待前记录观察序号，避免动作与订阅之间漏事件；去抖、事件合并、最大等待时间；动画不持续唤醒模型；pane 关闭/迁移/resize 时显式失效或重建观察；输出截断不得伪装为完整信息。

自动监视与手动模式均需支持。默认自动监视并按条件唤醒 Agent；手动模式仍后台检测并显示结果，由用户点击继续，不自动唤醒 Agent。自动触发范围、频率及任务展示采用本轮确认规则，见决策记录第 4、5、15、19 项。

## 接管 UI 与操作权

顶部单行示意：

```text
 COSMOS Taking over │ ⠹ Observing…
 COSMOS Taking over │ ⠸ Inputting…
 COSMOS Taking over │ ⠼ Cursor
 COSMOS Taking over │ ⠴ Waiting…
 COSMOS PAUSED
```

后台等待时隐藏顶栏；上例 Waiting 仅用于尚未转入后台的短暂前台等待，PAUSED 不播放忙碌动画。

建议使用 Cosmos 语义色：Agent 紫、输入琥珀、指针青；不使用完整外框。动画仅重绘局部。应用光标与 Agent 指针相互独立，不用展示指针冒充应用真实光标移动。

状态行由 Cosmos UI 绘制，不写进 Shell 历史。同一 pane 的所有客户端都显示接管行，统一预留空间；接管开始和结束各调整一次布局，调整后重新观察，避免操作过程中反复 resize。所有工具坐标以应用内容区为准；具体尺寸映射沿用并适配现有 Tmux 客户端布局机制。

每个 pane 同时只有一个操作权持有者。人工事件先撤销操作权、取消未发送动作，再正常交给应用；过期请求不能继续输入。已发送的按键无法撤回。恢复必须重新观察。

人工暂停时将 Taking over 替换为 PAUSED，状态行持续保留，直到 Agent 结束该 pane 的控制任务；不因保留状态行而保留输入操作权。进入监视器后台等待或定时等待时，释放操作权并隐藏接管行；唤醒后重新观察、申请接管。人工暂停不得被定时器擅自解除。

## 调度器

首版能力：一次性定时唤醒、事件唤醒、事件加超时、周期任务（按间隔或每天固定时间）。

每日任务保存明确时区，默认采用创建时的服务主机时区，创建界面显示并允许修改。夏令时导致指定时刻不存在时，顺延至当天第一个有效时刻；重复时刻只执行第一次。按间隔任务与每日墙上时间任务分别计算，不将每日任务简单等同于每隔 24 小时。

候选接口（未冻结）：

```text
schedule.create(at / after, task, context)
watch.create(target, condition, timeout, task)
schedule.list / cancel / reschedule
```

保存任务目的、Agent 对话 ID、目标 session/pane 稳定 ID、触发条件、下一次时间、执行策略和历史记录。不保存旧坐标作为下次操作依据。

服务端持久保存：SSH 断开/UI detach 后继续；重启恢复；避免同一任务并发与重复唤醒。服务停止期间错过的单次任务补执行一次，周期任务合并补执行一次；执行前重新验证目标与条件，人工暂停任务保持暂停。所有输入仍受操作权和 Agent 权限约束，调度不授予额外权限。错误和有意义结果接入统一日志/通知。

## 建议模块边界（未冻结）

- observation：快照、分层读取、差异、应用能力与适配器协议。
- monitor：确定性检测、动画/输入信号、事件归一化。
- control：pane 操作权、撤销、输入队列、快照校验。
- scheduler：持久任务、watch、唤醒与恢复。
- agent adapter：工具协议、模型唤醒、语义验证。
- UI：接管状态行、指针、任务状态与手动操作入口。

遵守现有 Cosmos 事件、通知、Action、设置与键位接口；复用现有终端和渲染能力，不另起独立写屏路径。

## 实施记录：第二步底层（2026-10-30）

已接入跨 MCP 进程共享的 pane 操作权、随机令牌、旧请求拒绝与人工按键/粘贴/鼠标撤销。受控输入沿用原终端工具，并在投递前检查暂停标记；鼠标要求当前观察快照，布局/服务身份变化拒绝旧令牌。用户可通过 Actions/键位设置手动恢复或结束控制任务；恢复后必须重新观察和申请，结束不停止终端程序。接口与边界记录在 `docs/agent-control.md`。

本步是操作权底层，并非完整任务暂停：共享 Taking over/PAUSED 顶栏、彩色指针、Agent 正在运行的模型请求暂停/取消，以及监视器和调度器仍待后续接入。旧输入工具在没有控制任务的 pane 上暂保兼容；已进入控制任务的 pane 禁止借旧工具绕过暂停。当前运行时记录孤儿任务采用拒绝输入、由用户手动结束恢复的策略，尚无调度器重启恢复逻辑。


## 实施记录：共享接管顶栏（2026-10-31）

已实现 Taking over 顶栏与局部盲文动画、人工暂停后的静态 PAUSED，以及所有客户端共享显示。顶栏复用 TerminalSurface；真实预留行通过 Tmux 窗口级 pane-border-status=top 实现，窗口内非受控 pane 也有顶边位置，但不显示接管文字。第一个控制任务建立时预留，暂停/恢复不 resize，最后一个任务结束时恢复原来的局部选项或继承关系。申请操作权后重新观察，返回调整后的 snapshot_id 与 dimensions；工具坐标仍相对应用内容区。

此原生后端方案与最初“仅目标 pane 占行”的理想粒度存在窗口级差异，正式接口文档已说明。彩色指针、模型运行暂停、后台监视与调度仍未实现。


## 实施记录：独立指针与后台条件监视（2026-10-31）

已接入区别于应用光标的青色闪烁菱形指针；人工暂停、结束或布局失效时隐藏，遵守 reduced motion。新增后台终端监视工具，独立进程进行文字条件、正文行差异、局部重复帧和程序变化检测及超时；结果持久保存在运行时数据库并通知，条件满足不等于任务成功。可带控制令牌进入等待，释放操作权和顶栏。普通 cosmos stop 暂停监视，UI 重连恢复待检测项。接口见 `docs/agent-monitor.md`。

本步尚无模型自动唤醒、Bash 明确输入适配器、原生输出观察序号/瞬时事件不漏采样保证、任务侧栏/Tasks 总览和周期调度。当前采样文字网格，重复帧判断是推断；后台进程不调用模型、不恢复人工暂停，也不投递终端输入。运行时数据库不是未来的持久任务调度器。

## 2026-11-01：持久调度与原生生命周期闭环

按最新要求，本阶段任务管理首先落在透明背景的 Cosmos Tasks pop window，不扩展 OpenCode 侧栏。正式接口以 docs/agent-tasks.md、agent-monitor.md、agent-control.md 为准；上方各步“尚未实现”是当时记录，不代表当前能力。

已落地：

- 私有 SQLite 任务账本，一次性/间隔/每日时区调度，DST gap/fold 规则，错过时合并补执行，detach 后继续、stop 后保留与 UI 启动恢复。
- 原生 Session API 的认证 Unix 生命周期桥；后台条件/超时唤醒原对话，按消息 ID 重试 admission；不是往 Agent 输入框粘贴文字。
- 人工接管持久暂停整个对应对话，撤销旧输入 token、结束旧 run、取消实际模型流；等待期间已释放控制的目标也会暂停。用户显式恢复后重新观察，不重用旧坐标/授权。
- 跨原生进程的同对话串行和默认最多两个 primary turn；可取消排队；可配置间隔和运行时限。标题等辅助生成不算 primary turn。
- Tasks 选择任务后的紧凑按钮、记录、改期、模式、原生权限 Once/Reject；取消与发送 Ctrl+C 的“中断程序”分开。统一 Actions/键位分组和 Settings。
- Bash PROMPT_COMMAND 明确序号事件，监视器 bash_prompt 条件；不把静止画面当作输入等待。
- Taking over 盲文独立定时刷新，暂停显示单色 ⏸︎。Tasks 弹窗仅覆盖自身矩形，外侧 Reader 图形保持。

验证：独立 Tmux 的真实 Bash prompt 监视；Python 任务持久化/暂停/串行/补执行/DST/透明弹窗与动画回归；原生权限与跨进程租约测试；真实 native Session 对本地模拟模型 API 的 wake/busy/interrupt（确认流式 HTTP 连接被取消，无付费请求）。未构建发行包，未停止用户会话。

仍属于后续能力：通用 TUI 原生语义/密码控件适配、可直接 act 的高置信控件、样式/原生输出序号驱动的瞬时事件可靠收集、图片真实内容观察、更多进程/文件/Reader 事件的统一订阅。当前 watch 仍采样，不能保证捕获短暂事件；worker 无独立 crash supervisor（UI 重连/新注册恢复）。任务创建由 Agent 工具完成，改期弹窗目前使用 JSON 输入，没有额外图形化创建向导。
