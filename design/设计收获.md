  # Cosmos 设计收获汇总

  > 以 Tmux 为核心的可扩展终端工作壳。本文汇总评审结论、交互决定、视觉规范与实现提示。

  ## 1. 评审结论

  | 项目 | 结论 |
  |---|---|
  | 理念 | 清晰克制:默认就是终端,壳提供秩序,Mod 提供能力 |
  | 最大风险 | 工程难度被低估:Tmux 内的图像管理、窗格临时替换视图、无桌面 Rime 输入 |
  | 缺失内容 | MVP 与路线图、可量化验收指标、Mod IPC 形态、许可证选型(尤其 PDF 后端)、与 Zellij 等方案的对比 |
  | 建议 | 先做技术验证,MVP 先交付"中文输入 + 图片查看",Agent 与 PDF 后置 |
  | 备选路径 | 评估 Tmux control mode + 独立前端,换取更低的上游同步成本 |

  ## 2. 候选区(中文输入)

  ### 位置与行为

  - 覆盖在光标下方的 2 行,只画在客户端绘制层。
  - 不改 PTY 尺寸,不写窗格 grid 和滚动历史。
  - 光标下方不足 2 行时,改放光标上方,顺序不变。
  - 右侧空间不足时整体左移,不截断候选。
  - 不超出当前窗格边界。
  - 结束后只需把覆盖区标脏重绘。
  - 多客户端互不显示。

  ### 内容

  | 行 | 内容 |
  |---|---|
  | 第 1 行 | 预编辑串;原光标处不重复显示 |
  | 第 2 行 | 候选(序号加词)和当前高亮项的释义;释义异步补全,不阻塞上屏 |

  ### 色块规则(简化版)

  - **候选之间不留间隔,不画分隔符。**
  - 高亮项:强调色底(`acc`)加反色文字。
  - 非高亮项:`base` 与 `raised` 两种底色**交替**,相邻候选靠明暗区分。
  - 序号用 `mute` 弱化,词用 `fg`。
  - 释义:单独的 `ok` 淡底块,位于最右。
  - 空间不够时先截断释义,再减少候选数,保证候选完整。
  - 按显示宽度计算,中文占 2 列。

  ````text
  [ nihao ]                                  ← 预编辑,raised 底、橙色下划线
  [1你好][2拟好][3泥壕][4尼好][ hello ]        ← 高亮蓝、其余明暗交替、释义淡绿
````

  ## 3. 统一调色板

  代码和样式里**只写角色名,不写 RGB**。主题由一张表决定,深浅主题用同一套角色。

| 角色           | 用途                          |
| -------------- | ----------------------------- |
| `bg`           | 窗格内容底色                  |
| `base`         | 状态栏、浮层、预览间隙        |
| `raised`       | 标签、标题条、交替底色        |
| `hi`           | 编号块、页码块                |
| `fg` / `mute`  | 正文 / 次要文字               |
| `acc` / `accl` | 焦点与选中 / 按键块、编号高亮 |
| `ok`           | 当前窗口、正常                |
| `warn`         | 后台待处理、Leader 已按下     |
| `err`          | 异常                          |
| `on`           | 压在强调色上的文字            |
| `view`         | 图片与 PDF 空白底             |

  对应 Tmux:`status-style`、`mode-style`、`pane-border-style` 等选项统一由这张表下发。

  ## 4. 状态栏

  ````text
  cosmos  1 shell  2 vim  3 agent▌  4 logs  5 docs                  3 / 18  中
  ````

  - 当前窗口:亮色反色块加粗,不依赖颜色也能识别。
  - 其他窗口:`raised` 暗块。
  - 后台待处理:1 列宽的 `warn` 小块,不弹窗、不抢焦点。
  - PDF 页码:仅在 PDF 查看时出现。
  - 输入法状态:一个小块;组字时变为 `warn` 色。
  - **不显示快捷键提示。** 按下 Leader 后只多出一个 `^A` 小块,表示"等待下一键"。

  ## 5. 按键提示策略(新)

| 规则          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| 不常驻        | 状态栏、浮层、窗口切换器底部、查看器都不放按键提示行         |
| 快捷键触发    | `^A ?` 打开壳级帮助;在窗口切换器和查看器内按 `?` 打开本上下文帮助 |
| 帮助就地显示  | 小浮层,按 `?` 或 `Esc` 关闭,返回来源                         |
| Leader 等待态 | 只显示 `^A` 小块;可选地,停顿超过设定时间后自动显示 which-key 式提示(默认关闭) |
| 命令与键一致  | 同一动作既可由命令调用,也可由快捷键调用,帮助内容由同一份操作注册表生成 |

  ## 6. 窗口切换

  基于 Tmux `choose-tree` 改造,临时替换当前视图,上方列表、下方预览。

  ````text
  窗口  会话 cosmos  共 5 个
  1   shell      ▇          ░▒▓
  2 ● vim        ▇ ▇        ▒░▓          ← 选中行用强调色铺满整行
  3   agent      ▇          ▓▒░  ▌
  预览  vim  2 个窗格
  %0 vim            %1 vim              ← 按真实布局排列的窗格预览
  ````

  - 列表行:编号块、当前窗口标记(`ok` 色块)、名称、窗格数色块、活动热度、待处理小块。
  - 预览:按 `window_layout` 的真实布局显示;窗格间靠底色差分隔,不画线。
  - 焦点窗格的标题条用 `acc`,其余用 `raised`。
  - 热度条为可选项。若保留,只在有活动时显示,并减少渐变层数。从截图看,多段渐变偏杂,建议改为 3 档纯色。
  - 底部不放提示行,按 `?` 查看。
  - 退出后恢复原窗口、焦点和滚动位置。

  ## 7. 图片与 PDF 查看

  - 临时替换当前窗格视图,不终止底下的进程。
  - 无工具栏、无属性栏、无额外边框。
  - 默认保持比例、完整适配。
  - PDF 只在状态栏显示 `3 / 18`。
  - 操作:缩放(`+ -`)、适配(`0`)、移动(方向键)、退出(`q` / `Esc`)、帮助(`?`)。PDF 另有翻页(`n p`)和跳转页码(`g`)。
  - 跳转输入条为单行 `warn` 标签加 `raised` 输入块。
  - 空白底用 `view` 角色。
  - 真实实现走 Kitty 图形协议;原型中的半块字符仅用于验证交互。

  ## 8. 实现要点(对应 Tmux)

| 需求     | 实现位置                                                     |
| -------- | ------------------------------------------------------------ |
| 候选区   | 客户端绘制层(`screen-redraw` / `tty`),只读窗格 grid,不写入   |
| 脏区域   | 候选出现、翻页、移动、消失都要标记新旧两块区域               |
| 窗口预览 | 复用窗格 grid 缓存和 `window_layout`                         |
| 活动热度 | `window_activity`、`monitor-activity` 及输出速率             |
| 上游同步 | 补丁集中在少量钩子,自有绘制逻辑放独立文件                    |
| 快速原型 | 先用多行状态栏、`display-popup`、`choose-tree` 验证交互,再改 C 代码 |

  ## 9. 原型踩过的坑

| 问题                         | 教训                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| 选中行蓝条没有铺满右边框     | **行尾补位色必须用该行自己的底色**,不能用固定底色            |
| 边框与内部有色差             | 边框和内部统一用同一角色(`base`)                             |
| `█ ▁▂▃ ◆ ▏` 等字符宽度不一致 | 东亚模糊宽度字符在不同终端占 1 或 2 列。带状态的元素一律用**带背景色的空格** |
| 配色零散                     | 颜色集中到调色板,只引用角色名                                |
| 判断截图时凭推测             | 先对照现象再下结论,不确定就让对方确认                        |

  ## 修改后的决定

  2. 释义范围:只显示高亮项,还是每个候选都带短释义。

  4. 窗口切换器:列表是否按"会话 / 窗口 / 窗格"折叠成树。==是==
  5. 热度条:保留(简化为 3 档)还是移除。
  6. 浅色主题:正式提供还是只保留调色板扩展点。
  7. Leader 等待态是否启用延迟显示的 which-key 提示。

## 这次的改动

- **候选色块**:取消间隔,非高亮项用 `base` 和 `raised` 交替,高亮项用强调色。
- **按键提示**:所有常驻提示行都去掉了,统一用 `?` 触发帮助。帮助内容由操作注册表生成,和命令入口保持一致。
- **热度条**:看你的截图,渐变段数偏多,显得杂乱。我在文档里建议改成 3 档纯色,也可以直接去掉。

需要的话,我可以把这两项改动合并进完整的交互原型。合并后,候选区、窗口切换、图片和 PDF 查看会放在同一个脚本里。
