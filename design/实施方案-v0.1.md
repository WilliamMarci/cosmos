## 1. 产品与首版边界

Cosmos 是在工作主机上运行的可扩展终端工作壳，基于独立定制的 Tmux。用户从另一台电脑通过普通 SSH 登录，执行 `cosmos`，即可创建或连接持续会话；连接电脑不需要 Cosmos 配套组件。SSH 断开不停止会话、查看器和 Agent，重新连接后重建终端显示。所有服务进程终止、主机重启后的应用进程恢复不在此承诺内。

本地运行与上述模型一致，只省去 SSH。首版 Linux x86_64，优先可下载解压的构建包。图像完整体验可以要求 Kitty 图形协议兼容终端，其他终端明确降级。不集成 SSH 连接管理或跨主机文件访问。

首版包括：终端复用、输入法、图片/PDF 查看、PDF 文本搜索、Yazi 文件能力、命令建议、完整 Agent、命令面板、统一设置、通知、窗口树与跨窗格输出搜索。模块可以分阶段完成，但单个阶段完成不等于首版交付。

后置项：EPS/SVG/ICO 格式接入、动画播放、OCR、文本选择与复制兼容层、远程文件协议、其他 Agent 后端、其他 Shell、其他平台、插件市场、第三方代码系统沙箱。ICO 后续接入时自动选择尺寸。

## 2. 进程与绘制架构

建议沿用 Tmux 客户端/服务端结构，把外层终端控制权保留在定制 Tmux 内；外部功能通过接口提交状态和呈现请求。不能在 Tmux 外再叠加一个自行解析全部 PTY 输出的终端前端。

```text
连接电脑上的终端
  └─ SSH（本地使用时省略）
      └─ cosmos attach / Cosmos Tmux client
          └─ Cosmos Tmux server：PTY、grid、会话、布局、客户端绘制
              ├─ 原有 Shell / Vim / OpenCode 等窗格进程
              ├─ Core bridge：对象、输入路由、呈现、事件
              └─ 本机私有 IPC
                  └─ cosmosd：注册、配置、通知、任务与模块管理
                      ├─ 输入法服务 → librime 或经验证的 IBus 适配
                      ├─ 文件服务 / 定制 Yazi
                      ├─ cosmos-view → 解码、栅格化、文本与缓存
                      ├─ 命令建议服务 → OpenCode
                      └─ Agent 工具桥 → Cosmos 对象与操作
```

`cosmosd` 是建议增加的协调进程，不拥有终端解析结果，也不接管 PTY；它重启后从 Tmux 重建对象目录。完整 Agent 的 TUI 和应用进程仍由 Tmux 持有。外部模块崩溃不应导致 Tmux 服务退出。

Tmux 补丁集中在客户端绘制、输入分发、视图切换、对象/事件桥接；自有代码独立文件维护，锁定上游提交。普通命令和 control mode 可用于对象操作与事件同步，但不能将其当成客户端浮层和图像合成的现成实现。[Tmux control mode 官方说明](https://github.com/tmux/tmux/wiki/Control-Mode)

### 2.1 实现语言建议

- Tmux 侧使用 C，复用既有事件循环、grid 和终端控制设施。
- 协调服务、查看器和协议工具建议 Rust，便于与 Yazi 改造共用工程环境，并保持明确的资源与取消生命周期。
- terminal_agent 先保留 Python 后端逻辑作为内部服务迁移，不要求同时重写。若构建包携带 Python 的成本过高，再依据测试迁移到 Rust；发布前必须决定打包路径。
- 不给每个逻辑模块独立启动常驻进程。需要隔离崩溃或阻塞任务时才拆进程；解码和栅格化进入可取消工作进程。

这些选型需要构建与依赖验证，不据此承诺完全静态链接或无需运行库。

## 3. 模块责任与公开边界

### 3.1 Core bridge

持有对象标识映射、布局快照、客户端能力、输入目标和呈现租约。提供受控 API，拒绝过期对象。维护每个客户端的焦点栈、按键模式和输出资源。

对象标识采用 `service_epoch + object_kind + native_id + generation`。服务重新创建后旧句柄失效；可复用的显示编号不作身份。API 返回对象版本，跨调用修改目标时重新验证。

### 3.2 操作、面板与设置

操作注册包含 ID、分类、参数、可用条件、显示名、上下文帮助和默认键位。键位与命令调用同一操作处理器。默认 Ctrl-B 为 Leader；Leader 后键位在原型阶段确认，设置提供键位子菜单。

命令面板默认搜索操作；设置和 Mod 进入子菜单。设置包含显示/主题、键位、输入法、通知、Mod、缓存和诊断。不把文件、会话、任务混入默认操作搜索。

主题使用既有角色 `bg/base/raised/hi/fg/mute/acc/accl/ok/warn/err/on/view`，首版深浅两套。默认简洁状态栏，可隐藏；帮助按需出现，不常驻铺满按键说明。

配置以版本化 TOML 为持久来源，UI 修改经校验后原子写回。只热更新支持热更新的字段，需重启的项目明确提示。Mod 用独立命名空间，不自行维护与面板冲突的键位入口。

### 3.3 输入法

统一接口：`create_context`、`process_key`、`get_preedit`、`get_candidates`、`select_candidate`、`commit`、`reset`、`destroy_context`。

开关按客户端保存，组字按 `(client_id, pane_id)` 保存。切换窗格保留组字，客户端断开取消组字；其他客户端不接收预编辑和候选。候选确认只发送提交文本，不隐含 Enter。

候选区在应用光标附近覆盖两行：预编辑、候选。优先下方，不足时放上方；不改变 PTY 尺寸，不写入 grid 或历史。默认每页六个，空间不足先减少候选数；极小区域需要紧凑降级并保留可访问操作，具体最小尺寸通过原型验证。候选间无空隙，交替底色，宽度按显示列计算。

首选技术建议：独立终端前端直接接 librime，以 IBus 的输入上下文和候选模型作为接口参考；先验证完整 IBus 路径是否能在无桌面环境带来实际复用收益。IBus 官方提供输入上下文、引擎、候选表和面板抽象，librime 提供 C API，但“终端版 IBus”并非已有可直接嵌入的完成品。[IBus API](https://ibus.github.io/docs/ibus-1.5/)；[librime API](https://github.com/rime/librime/blob/master/src/rime_api.h)

使用现有 `~/.config/ibus/rime/` 的 rime_ice 作为配置来源；包含词典、Lua、OpenCC 和相对符号链接依赖。建议导入配置和资源至 Cosmos 管理目录，词库写入独立用户目录，避免与桌面实例并发写同一数据库。导入不修改原配置；是否迁移既有用户学习数据在实现前以兼容性验证决定。

### 3.4 图形与查看器

`cosmos-view PATH` 统一打开 PNG、JPEG、WebP 静态帧和 PDF。入口可独立运行；集成时由 Cosmos 分配呈现目标，外部程序不直接越过合成层绘制外层终端。

拆分为源文件、格式适配、页面模型、文本模型、缓存调度、查看状态和位图输出。格式适配暴露探测、元信息、页面数、指定页渲染和可选文本提取。PDF 搜索需要文字位置映射及高亮；无文字层明确提示，不调用 OCR。

位图显示由客户端隔离的 image/placement 身份管理，经 SSH 发送图像数据，不使用连接电脑无法访问的服务器文件路径。资源建立、裁切、遮挡、删除、重连重传属于 Cosmos 图形层职责；协议透传本身不算通过验收。[Kitty 图形协议](https://sw.kovidgoyal.net/kitty/graphics-protocol/)

查看器键盘覆盖适配、缩放、平移、退出、帮助；PDF 增加翻页、页码跳转、搜索及下一/上一匹配。鼠标支持滚轮和拖动，具体修饰键在原型确认；输入事件在查看器区域内消费，避免传给底层应用。

PDF 后端建议先评估 Poppler 与 MuPDF，依据文本坐标、内存、取消能力、构建体积与分发许可证选择；不在本轮未经验证便确定依赖。

### 3.5 缓存与预加载

当前页最高优先级，前后各一页后台预加载。请求携带文档版本和请求代数，跳转取消过时任务；即使取消不能立即停止解码，也丢弃过时结果。

内存和磁盘各有独立上限，采用可回收策略，设置提供预算和清理。磁盘缓存退出可复用，正在显示资源保留有效引用；清理不得破坏当前画面。

键至少包含源身份与版本、页面、渲染尺寸/比例、颜色或透明度参数、后端版本。仅路径、mtime 和大小不能绝对保证内容身份；持久复用需内容指纹或可靠版本校验，验证成本可异步进行。

文件变化自动重载。采用防抖和可读取检查，不把短暂半写入结果替换当前有效视图；重载失败保留旧版并通知。页数减少时落到最近有效页，缩放和位置尽量保留。预览、PDF 与大图共用预算，单页像素数和解码内存有限额。

### 3.6 文件管理与左侧面板

保留选定上游 Yazi 版本的现有文件能力，统一改造 UI、布局、快捷键与操作入口；“保留能力”不代表所有外部预览器、插件和命令在缺失依赖时都能工作。实施前建立上游功能清单和依赖清单，逐项回归。

两种呈现：

1. 专用窗口：完整文件管理工作区。
2. 可折叠左侧 panel：顶部目录；上方主要区域列出当前目标窗格目录内容；下方仅在选中文件时显示预览，无选择不画预览。

面板必须记住关联的工作窗格，获得焦点后不能误将“当前窗格”改成面板自身。目录跟随使用可靠的 Shell 目录报告，无法确认时显示来源或保持最后已知值；文件面板自己导航不隐式 `cd` 原 Shell。

建议共用同一文件能力层，以两套呈现配置使用。官方有插件和键位配置，但尚不能据此保证左侧嵌入布局只靠配置完成；需要评估定制 Yazi 补丁。[Yazi 插件](https://yazi-rs.github.io/docs/plugins/overview/)；[键位配置](https://yazi-rs.github.io/docs/configuration/keymap/)

首版侧栏建议作为用户显式打开的受控 dock：打开/关闭时统一更新可用布局，不因选中文件或候选变化反复 resize。共享 PTY 尺寸沿用 Tmux 协调；客户端局部侧栏与共享布局之间的尺寸影响是必须验证的设计点，不能声称已解决。若技术验证不满足，先提交替代方案供审阅，不悄悄把侧栏换成普通自动分屏。

### 3.7 命令建议与完整 Agent

命令建议沿用 terminal_agent：目标目录与本次请求/命令历史进入提示，在专用后端工作区生成，禁用工具，单行命令回填 Bash 编辑缓冲区，再由用户修改执行。不能改为通用 `send-keys` 后自动 Enter。既有 C Readline 与 Python UI 的绘制职责需重新拆分，Shell 适配保留缓冲区和光标能力，Cosmos 接管外层辅助行呈现。

完整 Agent 由用户显式创建和选择多个专用窗口，各自关联后端任务，不自动分屏。任务记录包含后端类型、任务 ID、窗口关联、来源目录、运行状态和可恢复信息，不复制第二套模型对话作为真相来源。

建议通过本机 MCP 桥暴露 `list_sessions/windows/panes`、`inspect_pane`、`read_output`、`search_output`、`create_window`、`focus_target`、`send_input`、`close_target` 等工具。读取按需且有范围和字节上限；终端输出作为不可信上下文，不解释为工具授权。

写操作工具接入 OpenCode 权限配置；逐项验证 ask/allow/deny 实际效果，不能只展示一个确认提示就视为权限链成立。可信第三方程序不受此模型调用策略约束，首版没有系统沙箱。[OpenCode MCP](https://opencode.ai/docs/mcp-servers/)；[权限机制](https://opencode.ai/docs/permissions/)

### 3.8 导航与跨窗格搜索

窗口切换树按会话/窗口/窗格折叠，预览按真实布局显示，去掉活动热度。浏览不改变当前目标，确认才跳转，取消恢复来源。

全局输出搜索限于当前 Cosmos 服务仍保留的终端输出，不承诺 Shell 完整历史、已关闭窗格或磁盘日志检索。建议按查询截取有界快照并后台搜索，返回目标、片段、行锚点和快照版本。结果跳转前验证锚点，历史淘汰时降级并通知。首次打开不把全部历史建立永久索引；需要索引时再按性能证据引入。

### 3.9 通知与 Mod 管理

Mod 手动注册，manifest 包含身份、版本、协议范围、启动命令、声明能力、操作、配置和事件。使用 argv 启动，不把注册参数隐式拼接成 Shell 命令。状态为注册、启动、就绪、停止、失败；重启有退避和次数限制。

通知是统一呈现类型。记录来源、稳定 ID、修订、级别、文本、动作、是否待处理、去重键和时限。所有当前客户端收到同一服务事件，在各自全局右下角显示；普通通知超时，需要处理的保留，不抢焦点。高 1～2 行，按钮宽 3 显示列，溢出采用队列/合并，不扩展为常驻日志墙。

处理动作以服务端通知修订和 action token 原子认领，避免双客户端重复操作；处理结果同步所有客户端。普通关闭只保存客户端呈现状态。重新连接后先恢复未处理事项，已超时普通通知进入有界历史，不集中重播。

## 4. 状态与重连

Tmux server 持有应用进程、PTY、grid 与终端历史。cosmosd 持有模块目录、服务通知、任务关联与可重建元信息。查看器持有文档、页码、缩放和浏览状态；客户端持有焦点、能力、显示资源和临时输入状态。

断线时清除输入法组字和客户端图形资源租约；不结束服务会话、查看器任务和 Agent。重连重新探测尺寸、像素协议和终端能力，从逻辑状态重建资源；恢复不依赖旧客户端仍存活。

需区分共享工作状态与客户端差异：文档身份与任务可服务端保留；不同客户端的缩放、视口、焦点和资源不得互相覆盖。每个 attach 有新客户端身份；无可靠恢复标识时采用视图的默认恢复快照，提供选择入口，不猜测另一个仍在线客户端的私有交互状态。

查看器关闭返回进入前的窗格、焦点和滚动锚点，底层输出持续正常记录。历史已淘汰或窗格关闭时恢复最近可用状态，发简短通知。进程内存保留和主机重启后的持久恢复是不同保证。

cosmosd 崩溃时 Tmux 仍可操作；输入法服务失效恢复直通；查看器工作进程失败保留可用画面并允许退出；外部 Mod 超时释放焦点和绘制租约。

## 5. IPC 契约草案

建议同一主机私有 Unix socket，目录 0700，验证同 UID；控制消息使用有长度限制的 JSON-RPC 2.0。像素不放入大型 JSON，使用有界私有文件或文件描述符传递；由核心读取后发至终端，不给连接端发送远程本地路径作为显示依赖。

初始化协商 `protocol_major/minor`、模块能力、事件订阅和最大消息尺寸。每个异步请求带请求 ID、deadline、取消标识、对象版本；错误明确区分目标消失、版本过期、能力缺失、权限拒绝、忙碌和取消。

建议服务族：

- `objects.*`：列举、查询、版本校验及布局快照。
- `actions.*`、`settings.*`：注册、执行、读取与原子修改。
- `presentation.*`：申请/更新/释放覆盖区、dock、替换视图、通知；请求方声明目标和焦点策略。
- `input.*`：输入法事件、文本提交；Shell 回填使用单独的已验证缓冲区适配接口。
- `files.*`、`documents.*`：本地文件能力、打开、页面/文本、渲染与取消。
- `notifications.*`：发布、修订、动作认领、完成、客户端关闭、历史。
- `tasks.*`、`terminal.*`：后端任务关联、输出快照、搜索和受控终端操作。

事件包括对象变化、目录变化、客户端 attach/detach/resize、能力变化、文件变化、任务状态、通知修订、Mod 失败。每条有序号；重连发现序号缺口时请求状态快照，不把事件流当永久数据库。

低延迟输入路径使用有超时的引擎请求和客户端内最小路由，不等待文件预览、网络或 PDF 工作完成。性能阈值在原型测量后确定，不能先声称每键延迟已满足某个数值。

以下仅是计划，不在本轮创建实现目录或移动旧项目。

```text
cosmos/
  design/                       需求记录、方案、协议和验收说明
  upstream/                     锁定的 Tmux/Yazi 来源与补丁清单
  native/tmux/                  核心桥、绘制、输入和视图补丁
  crates/
    protocol/                   公共类型、版本、错误与事件
    cosmos-cli/                 启动、attach、命令与诊断
    cosmosd/                    协调、配置、通知、模块和任务
    presentation/               公共布局/主题描述
    ime-service/                输入法接口与引擎适配
    image-service/              资源与缓存调度
    viewer/                     文档、页面、文本与查看交互
    files/                      文件能力与 Yazi 适配
    agent-bridge/               MCP 工具与任务关联
    search/                     输出快照与搜索
  adapters/bash/                Readline、缓冲区和目录报告
  services/command-agent/       迁移后的 Python 生成逻辑（如保留）
  mods/                         自有模块 manifest 与配置
  themes/                       深色、浅色角色表
  packaging/                    构建包、依赖、许可证与校验清单
  tests/                        协议、集成、终端与故障验收
  terminal_agent/               当前实践原位置，迁移完成前保留
```

Tmux/Yazi 修改应记录上游提交、补丁目的、影响范围与回归用例，不把上游全部代码和自有业务混在一处。源码复用分发依照锁定版本实际许可证整理源代码、版权和构建说明；Yazi 许可证应在打包前按选定提交核实。[上游 LICENSE](https://github.com/sxyazi/yazi/blob/main/LICENSE)

## 7. terminal_agent 迁移顺序

1. 固定当前功能基线，保留已有测试，不先重写后端和 UI。
2. 抽出生成、模型配置和错误解析接口，保留实际目录与后端工作区分离。
3. 将状态配置迁到 Cosmos 命名空间；只读导入旧状态，迁移不复制认证进入日志或配置。
4. 将辅助行绘制交给 Cosmos，Readline 适配只承担缓冲区、光标和 Bash 生命周期；验证没有两套重绘竞争。
5. 将完整 Agent 入口改为显式任务窗口和 Cosmos 工具桥，不声称沿用原任务。
6. 通过行为回归后移除独立产品入口；旧目录清理另行记录，不在设计阶段执行。

已有 backend 明确禁用工具，保留这一命令建议边界；完整 Agent 的工具权限是另一条适配链。既有测试成功不能替代定制 Tmux、SSH 和多客户端现场验收。

## 8. 分阶段交付与验收

### 阶段 0：技术验证和依赖锁定

验证定制 Tmux 客户端覆盖区、图片裁切与遮挡、替换视图、侧栏尺寸协调、IBus/librime 接入、PDF 文本坐标、Yazi 两种呈现、OpenCode 权限工具链。锁定版本、构建基线与许可证清单。

出口：每项产出最小运行证据和失败边界；若侧栏或图像方案不成立，先修订设计，不能用普通分屏或只显示一张图片冒充满足需求。

### 阶段 1：壳与公共接口

完成独立服务/socket、启动 attach、对象 ID、操作注册、主题、命令面板、配置、通知和 Mod 生命周期。

验收：Ctrl-B/命令入口一致；应用输入默认直通；配置非法时不破坏上次有效值；双客户端通知动作不重复；Mod 崩溃后焦点和键位可恢复；SSH 断线会话继续。

### 阶段 2：输入法与 Bash 建议迁移

完成 rime_ice、两行候选、客户端开关、窗格组字、Bash 缓冲区适配及命令建议。

验收：Shell/Vim/Agent 中一致组字；不同客户端不串候选；切窗格保留、断线取消；无隐式回车；中文宽度、缩放、长命令和绑定恢复；生成失败保留命令草稿；模型不执行命令。

### 阶段 3：图形、查看器和 PDF

完成位图格式、PDF 页面与搜索、高亮、缓存、预加载、更新重载、鼠标及独立入口。

验收：普通 SSH 真传输；遮挡/窗口切换/resize 不残影；无图形支持可退出且明确降级；快速跳页无旧结果覆盖；半写入文件保留旧图；缓存预算生效；退出恢复现场；重连后页面和任务仍可用；无文字 PDF 不显示虚假搜索结果。

### 阶段 4：文件能力、导航与全局搜索

完成定制 Yazi 窗口与可折叠侧栏、上下区域、条件预览、真实布局窗口树和跨窗格搜索。

验收：对选定 Yazi 版本建立功能等价清单；重命名、复制、移动、删除等在临时目录实测；面板焦点不打断目录关联；无选择不预览；键位和主题统一；搜索只检索保留输出，历史淘汰正确降级。

### 阶段 5：完整 Agent

完成多个任务窗口、会话发现、按需输出、Cosmos 工具操作和权限确认。

验收：列出本服务所有对象；不自动发送全部历史；工具 deny 实际阻止动作，ask 待确认才执行；对象关闭/复用后不误操作；任务窗口断线后持续存在；不同任务不串关联。

### 阶段 6：构建包与首版验收

Linux x86_64 解压安装，在本地与目标服务器测试；记录最低运行库、附带组件和外部依赖。升级使用并排版本，不替换正在运行的服务二进制；旧服务未退出时不强制迁移对象和任务。

验收矩阵至少覆盖：直接终端、普通 SSH、支持/不支持图形、单/双客户端、resize、detach/attach、组件崩溃、缺依赖和只读配置。嵌套复用单独记录兼容性，不因普通 SSH 成功宣称全部支持。交付包括校验清单、诊断命令和已知限制。
